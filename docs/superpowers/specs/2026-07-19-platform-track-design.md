# Platform Track — Design

**Date:** 2026-07-19
**Scope:** Sub-project 3 of 5 in the 10x initiative. Turns the app from "eight hand-wired pages" into a platform: one tool registry driving every surface, a universal capability layer for all tools, a real command palette, a genuine offline PWA, and provable privacy (removing the app's only outbound data flows). This is the prerequisite for cheap tool expansion (sub-project 4).

**Out of scope:** new tools (sub-project 4), smart-paste detection and tool chaining (later — the registry's `detect` hook is designed now, implemented later), analytics (open question below), WebMCP/MCP (sub-project 5).

## Goals

1. Adding a tool = adding one registry entry + one component. No more 8-file surgery (router, HomeView, palette, footer, sitemap ×3, SEO config today).
2. Every tool gets the flagship layer: persistence, share, copy feedback, samples where sensible — not just Text Compare.
3. The privacy claim becomes architecture: zero network egress after first load, offline-capable, install-prompt PWA.
4. The palette becomes a daily-driver habit: fuzzy, recents-aware, keyboard-first.

## Design decisions

### D1 — Central tool registry

New `src/tools/registry.ts` — pure data, importable from both the app and `vite.config.ts` (no Vue imports; icons are PrimeIcons class strings):

```ts
export interface ToolDef {
  slug: string                 // 'text-compare' — route is /tools/<slug>
  name: string                 // 'Text Compare'
  shortName: string            // tab label
  description: string          // meta description + palette subtitle
  icon: string                 // ONE icon string, used by every surface (fixes today's HomeView/palette divergence)
  category: 'Text' | 'Code' | 'Encoding' | 'Security' | 'Time'
  keywords: string[]
  seoKey: string               // key into config/seo.ts tools map
  footerGroup: 'tools' | 'utilities'
}
export const TOOLS: readonly ToolDef[]   // all 8 tools
```

Component loaders stay in `src/router/index.ts` as a `Record<slug, () => import(...)>` (lazy imports can't live in the pure module). Consumers rebuilt on the registry:
- **Router:** `toolRoutes` generated by mapping `TOOLS` (meta title/description/canonical composed from the def + seo config).
- **HomeView tabs + CommandPalette entries + AppFooter groups:** generated, deleting three hand-maintained lists.
- **Sitemap:** the `vite.config.ts` sitemap plugin imports `TOOLS` and derives routes — deleting `SITE_ROUTES`.
- **Prerender:** `scripts/prerender.js` derives its route list from `dist/sitemap.xml` (already regenerated each build) instead of its own hardcoded array — deleting the third route list without making the script import TS.
- `config/seo.ts` keeps per-tool FAQ/HowTo content (long-form data), keyed by `seoKey`; the registry is the single source for identity (name/description/category/route).

Guard test: a unit test asserts registry invariants (unique slugs/paths, every seoKey resolves, every icon is a `pi pi-` string) and — the drift-killer — that router route names, palette entries, and footer links exactly equal the registry (mount-level tests).

### D2 — Universal tool chrome (capability layer)

Not a visual re-skin — a capability composable plus two small components, adopted tool-by-tool:

```ts
// src/composables/useToolState.ts
export function useToolState<T extends Record<string, Ref<unknown>>>(
  toolSlug: string,
  fields: T,
  opts?: { debounceMs?: number }   // default 800
): {
  flushSave(): void
  clearSaved(): void
  restored: boolean                // true when a saved session was restored on mount
}
```

- Persists the named fields to `localStorage` key `devyantra:<slug>:state` (versioned envelope `{v: 1, fields}`, strict-validated on load — same hardening philosophy as the diff share state). Registered after restore, saves only on post-restore change (the fix-pack lesson, generalized).
- Adopted by all 7 non-flagship tools (Formatter input+type, Hash input+selected algos, Base64 input+mode, JWT input, Timestamp inputs+unit, Character Count input, Delimiter input+options). Text Compare keeps its existing `useShareState` (already superset).
- `src/components/tool/ToolActions.vue`: a standard action-row component (slots for tool-specific buttons) providing Copy-result (via `useClipboard`), Clear-with-Undo (the established toast pattern), and optional Sample. Each tool passes its bindings; adoption replaces the seven inconsistent ad-hoc button rows where they exist, adds the layer where they don't.
- URL sharing for all tools is deliberately **deferred** — `useShareState`'s generalization needs per-tool payload design; the registry's `ToolDef` gets no share flag until then (YAGNI).

### D3 — Command palette v2

`src/components/CommandPalette.vue` rebuilt on the registry:
- Entries: all tools (icon/name/description from `TOOLS`) + actions (Toggle theme, Copy current URL, Open feedback).
- **Fuzzy matching** (no dependency): subsequence scorer — +3 word-boundary hit, +2 consecutive, +1 scattered, normalized by target length; case/diacritic-insensitive (`String.prototype.normalize('NFD')` strip). Unit-tested with ranking cases (`"tc"` → Text Compare first; `"b64"` → Base64; `"jwt"` beats Delimiter for `"j"`+`"w"`+`"t"`).
- **Recents:** last 5 invoked entries in `localStorage` (`devyantra:palette:recents`), shown first on empty query with a "Recent" section label.
- Selected-item behavior, dialog semantics, and Cmd+K binding unchanged.

### D4 — Real PWA (offline + installable)

- Add `vite-plugin-pwa` (devDependency — the one new dependency of this sub-project; hand-rolling Workbox-grade precache manifests is not a good use of anyone's time). Config: `registerType: 'autoUpdate'`, precache the app shell (`**/*.{js,css,html,svg,png,ico,woff2}`), `navigateFallback: '/index.html'` with the SPA rewrite semantics matching vercel.json.
- Proper manifest icons: generate `icon-192.png`, `icon-512.png`, `icon-512-maskable.png` (brown-on-paper, from `favicon.svg` via the existing resvg toolchain — new script `scripts/generate-icons.js`, wired into `generate:og`'s pattern); manifest updated (name/short_name/theme/background already correct post-fix-pack).
- In-app affordances: an unobtrusive "Install app" entry in the footer when `beforeinstallprompt` fires; an offline-ready toast on first SW activation ("DevYantra works offline now"); an `navigator.onLine`-driven pill in the header when offline ("Offline — everything still works").
- E2E: with the built app served, `context.setOffline(true)` after first load → reload → app shell renders and a tool computes (hash of "hello" still correct offline).

### D5 — Provable privacy: zero egress

Two outbound flows exist today; both die:

1. **Formspree feedback form** (the audit's privacy contradiction): `FeedbackForm.vue`'s POST is removed. The feedback page becomes static links — "Report a bug" / "Request a feature" / "Discussions" → the GitHub URLs (new-issue templates already exist in the repo). No network call, no third party. The `Cmd+Shift+Enter` submit binding dies with the form.
2. **Google Fonts** (`@import` in `theme.css` — render-blocking AND third-party): self-host JetBrains Mono. Vendor the woff2 files (Latin 400/500/600/700 + italic 400) into `public/fonts/`, replace the `@import` with `@font-face` declarations (`font-display: swap`), delete the `preconnect` hints in `index.html`. Bonus: kills the render-blocking import flagged in the audit.

- **Headers:** add a Content-Security-Policy to `vercel.json`: `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self'; connect-src 'self'; worker-src 'self'; frame-ancestors 'none'` (connect-src 'self' is required for the service worker's precache fetches; the app makes no other requests). `'unsafe-inline'` for styles is required by Vue's injected component styles unless we add nonce plumbing — accepted, documented.
- **The proof page:** `/privacy` route (registered via the registry mechanism as a page, not a tool — a `pages` list alongside `TOOLS`): states the architecture (no backend, no telemetry, CSP blocks egress, open source), and shows a "verify it yourself" section (open devtools → Network → use any tool → observe zero requests). Footer links to it; the header's existing privacy badge links to it.
- E2E: a network-request recorder over a full tool-using session (load → hash → format → diff → palette) asserts every request URL is same-origin.

### D6 — Analytics: none (open question for Shaurya)

The research says winning tool sites run on habit (direct traffic), and we currently fly blind. This spec ships **no analytics** — it would contradict D5's zero-egress claim the day it lands. The `/privacy` page states "no telemetry of any kind." If usage data becomes worth having, the options (self-hosted Plausible on a subdomain with a disclosed opt-out, or none) are a user decision recorded here as open — nothing in this track precludes it.

## Component/file structure

```
src/tools/registry.ts            # pure ToolDef data (+ pages list)
src/composables/useToolState.ts  # per-tool persistence
src/components/tool/ToolActions.vue
src/views/PrivacyView.vue
scripts/generate-icons.js
public/fonts/*.woff2             # vendored JetBrains Mono
```
Modified: router (registry-driven), HomeView, CommandPalette (v2), AppFooter, vite.config.ts (sitemap from registry, PWA plugin), scripts/prerender.js (routes from sitemap), theme.css (@font-face), index.html (drop font preconnects), vercel.json (CSP), FeedbackForm/FeedbackView (static), the 7 tool components (useToolState + ToolActions adoption).

## Error handling

`useToolState` load failures fall back to empty state silently (corrupt storage never breaks a tool); SW registration failure logs once and the app runs normally (PWA is progressive); install-prompt absence hides the affordance.

## Testing

- Unit: registry invariants + drift guards; fuzzy scorer ranking table; useToolState (restore-before-watch ordering, strict validation, flush, clearSaved) reusing the share-state test patterns.
- Component: palette (fuzzy filter renders ranked results, recents section), ToolActions (copy toast, clear-undo).
- E2E: per-tool persistence smoke (enter input → reload → restored) across all 7 adopters; palette fuzzy + recents flow; offline reload + offline compute; zero-egress recorder; feedback page has no form POST; footer/tabs/palette parity with registry (counts + labels).
- Full sweep at the end (the a11y suite must stay green — the palette rebuild keeps its dialog/ARIA contract).

## Risks

- `vite.config.ts` importing `src/tools/registry.ts`: esbuild handles TS imports in config; the module must stay dependency-free (a unit test imports it in isolation to enforce).
- CSP can break in preview vs production if Vercel injects anything; mitigation: test the built app with the same headers locally (`serve` + header emulation in the e2e server config) before relying on it.
- Service worker + Vercel SPA rewrites interplay: `autoUpdate` with `navigateFallback` is the standard combination; the offline e2e is the guard.
- Font subsetting: vendored woff2 (5 weights) ≈ 300–400 KB cached once; acceptable, and `font-display: swap` keeps first paint clean.

## Definition of done

Gates + full chromium e2e green; `npm run build:seo` produces a sitemap/prerender set identical in URL coverage to today's; the built app passes the zero-egress e2e and works offline; deleting a tool from the registry removes it from every surface (spot-verified in a test by filtering the registry).
